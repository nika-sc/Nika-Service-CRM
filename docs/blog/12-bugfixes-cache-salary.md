# Багфиксы: Redis-кэш, дашборд и смена мастера с зарплатой

5 августа 2026: серия исправлений стабильности CRM — поломки из‑за Redis, дашборда и перевода начислений при смене исполнителей.

## 1. Добавление услуги/запчасти: 500 и «Unexpected token»

**Симптом:** в карточке заявки кнопка добавления услуги или запчасти отвечала HTML-ошибкой вместо JSON; в консоли браузера — `Unexpected token '<'`.

**Причина:** кэш Redis сохранял объект заявки (`Order`) как строку. Следующий запрос читал строку и падал при обращении к полям вроде `status_id`.

**Исправление:**
- кэш моделей `order` / `customer` / `device` отключён;
- в JSON для моделей используется `to_dict()`;
- проверка «можно ли редактировать» идёт через SQL, без загрузки объекта из кэша.

## 2. Разный тип данных из Redis и из памяти

**Симптом:** плавающие ошибки на главной и в отчётах (`%.0f` / `total_sum`, даты, ключи справочников) — то работает, то нет.

**Причина:** после промаха кэша в Redis уходил JSON (даты → строки, `Decimal` → число/`str`, ключи dict → строки), а в память клался «сырой» Python-объект. Hit из Redis и hit из memory давали разные типы.

**Исправление:**
- единая нормализация `_to_json_safe` перед записью и в Redis, и в memory;
- ключи usage-counts сразу как `str(id)`;
- в шаблонах дашборда/отчётов для денег — `|float` как защита;
- на WORK очищены префиксы кэша после выката.

## 3. Смена мастера/менеджера на проведённой заявке

**Симптом:** заявка уже проведена, зарплата начислена; смена мастера или менеджера не сохранялась, начисления оставались у прежнего сотрудника.

**Причина:** закрытый статус блокировал всё редактирование; отдельного сценария «сменить исполнителя и перенести ЗП» не было.

**Исправление:**
- в закрытой заявке кнопка **«Сменить исполнителей»** (рядом с карандашом);
- мастер и менеджер сохраняются даже при `blocks_edit` / финальном статусе;
- существующие начисления **переносятся** на нового сотрудника (суммы и логика периода по оплатам сохраняются);
- при обычном редактировании открытой заявки перенос тоже выполняется, если сменили исполнителя.

## Что проверить после обновления

1. Открыть заявку → добавить услугу/запчасть — ответ JSON, без 500.
2. Главная и отчёты с Redis — без TypeError на суммах.
3. Проведённая заявка с начислениями → «Сменить исполнителей» → в блоке зарплаты и в отчёте ЗП фигурирует новый мастер/менеджер.

## Для администраторов

После деплоя на среде с Redis достаточно перезапуска web и при необходимости очистки ключей кэша (`dashboard_*`, `reports_*`, `ref_*`) — полный `FLUSHDB` не обязателен, если Redis общий с Socket.IO.
